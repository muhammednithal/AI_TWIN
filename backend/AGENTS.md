# Backend guide

Read the root `AGENTS.md` first.

- `cmd/server` composes dependencies and manages process lifecycle. No global database connection.
- `internal/platform/settings` loads and validates environment configuration. `internal/platform/ai` owns the Gemini REST transport behind a small interface.
- `internal/workspace` is a vertical module: explicit data models, auth, account-scoped HTTP operations, transactions, retrieval, and tests. Keep handlers grouped by resource. Extract services only when a boundary or shared use case warrants it.
- Pass the request context through SQL and provider calls. Never use unbounded background goroutines for account data processing.
- Use parameterized SQL/GORM clauses and `validID`, `twin`, `session`, or `ownedMemory` ownership guards. Add negative authorization tests when introducing endpoints.
- JSON errors are `{ "error": "safe message" }`. Do not send raw database errors, prompts, provider bodies, or credentials to clients.
- Chat generates before persistence, then atomically writes the session/message pair. The current in-process lock and rate limits are intentionally single-instance; see `docs/DEPLOYMENT.md` before scaling horizontally.
- Gemini vectors are compatible only within the same model/representation. Changing embedding models requires a deliberate reindex migration. The default text embedding model is retained for legacy vector compatibility.
- Preserve legacy table names and columns. UUIDs are generated by the application; fresh installs do not require UUID extensions. Schema changes run only with `go run ./cmd/server -migrate`.
- Use `sqlmock` for focused SQL ownership/failure tests. These tests do not prove a real PostgreSQL migration succeeds. Add disposable PostgreSQL integration tests for migration-dependent work.

Tests must not read real API keys or mutate an existing database. Run Go formatting, vet, tests, and build before handoff.

Project/task code is grouped in `projects.go`, `project_memory.go`, `project_import.go`, `task_context.go`, `tasks.go`, and `decisions.go`. Use `project` and parent-row locking for ownership and consistent context. Result/snapshot fields are immutable; only review state is editable. Context signing is deterministic and covers prompt version, project instructions, objective/type, and memory content/version/provenance. Revalidate before generation and in the persistence transaction. Keep request IDs stable for retries. New project notes are stored without provider calls.

`project_integration_test.go` provisions its own random schema only when `TWIN_TEST_DATABASE_URL` is explicitly local and ends in `_test`. CI supplies a disposable PostgreSQL service. Report local skips separately from passes.
